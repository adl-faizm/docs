XLSmart Design System is a living system maintained by a cross-functional team. If you use the design system to build products, you can contribute by requesting new components, reporting bugs, proposing token changes, or submitting design feedback.

## Request a component

Before requesting a new component, use the following steps to make sure your request is clear and actionable:

1. Check the existing [component library](/components/button) — the component you need may already exist under a different name
2. Open an issue in the design system repository with the label `component-request`
3. Describe the use case and how the component would be used across products
4. Attach reference designs or Figma frames if available
5. The design system team will review your request and communicate a decision through the issue

<Info>Components are added to the system when they are needed by at least two different product teams. Single-use components should live in your product's local component library.</Info>

## Report a bug

If a component is broken, inaccessible, or behaving unexpectedly:

1. Confirm you are using the latest version of `@xlsmart/design-system`
2. Open an issue with the label `bug` and include:
   - The component name and version
   - Steps to reproduce
   - Expected vs. actual behavior
   - Screenshots or a minimal reproduction if possible

## Propose a token change

Design tokens power every component in the system. Before proposing a change:

- Review the [Design Tokens](/foundation/colors) documentation to understand the current token structure
- Consider the downstream impact on all components that use the token
- Submit your proposal as a ticket with the label `token-change`, including a rationale and the proposed new value

<Warning>Token changes are breaking changes. They are batched into major version releases and communicated through the [Changelog](/resources/changelog).</Warning>

## Design feedback

For feedback on visual design, interaction patterns, or UX improvements, open a discussion in the design system repository with the label `design-feedback`. Attach Figma links or screenshots to keep the conversation grounded and actionable.

## Code of conduct

All contributors are expected to be respectful, constructive, and inclusive. The design system team reviews all contributions and reserves the right to decline requests that do not align with the system's principles. See the [Design Principles](/resources/design-principles) page for the values that guide design decisions.
